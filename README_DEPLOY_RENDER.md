# Deploy AI Travel Planner to Render (Free Plan)

This guide deploys the existing Streamlit UI and `travel_planner` package. It does not add paid services or make API calls during build.

## Files expected in your project root

Before deploying, confirm these already exist in your repository:

- `web_app.py` (the working Streamlit UI with comparison tab)
- `pyproject.toml` with Streamlit in the main dependencies
- `uv.lock` committed after `uv add streamlit`
- `travel_planner/` source package, including `utils/live_travel_provider.py` and `utils/web_research_once.py`
- `render.yaml` from this pack

## 1. Restore local development dependencies first

Your earlier `uv sync --locked` removed development tools. On your Windows computer run:

```powershell
uv sync --extra dev --locked
python -m pytest tests\unit -q
```

Do not run `uv sync --locked --no-dev` locally while you still need pytest. Render uses `--no-dev` only in its separate cloud build environment.

## 2. Check secrets before committing

Make sure `.env` is ignored by Git. Never commit `.env`, API keys, `.repair-backups/`, or local repair scripts.

Verify the repository state:

```powershell
git diff --check
git status --short
git remote -v
```

If your `origin` points at the upstream project you do not own, create an empty GitHub repository under your own account and configure it as `origin` before pushing. Do not delete the upstream remote if you still want it for reference.

Stage only intended project files (application, tests, `pyproject.toml`, `uv.lock`, `.gitignore`, `render.yaml`, and relevant README changes). Review the staged diff before committing.

```powershell
git diff --cached --check
git diff --cached --stat
git commit -m "Deploy AI travel planner MVP"
git push -u origin HEAD
```

Use `git add` with explicit paths rather than blindly adding everything.

## 3. Create the Render service

1. Sign in at https://render.com/.
2. Choose **New + → Blueprint**.
3. Connect your own GitHub repository containing `render.yaml`.
4. Review the proposed service `ai-travel-planner`, region Singapore, Free plan, build command, and start command.
5. Add the values for the environment variables marked `sync: false` in the Render dashboard. Paste secrets directly there, never in GitHub or this chat.

Required for itinerary generation under the current app/config:

- `GEMINI_API_KEY`
- `SUPABASE_URL`
- `SUPABASE_KEY`

Used for web research and the price-comparison tab:

- `TAVILY_API_KEY`
- `FIRECRAWL_API_KEY`
- `SERPAPI_API_KEY`
- `RAILRADAR_API_KEY`

The free flight/hotel/rail providers are optional for deployment, but the UI will show their functions as unavailable if their key is empty. Keep `OPENAI_BASE_URL` and `DEFAULT_MODEL` values defined by `render.yaml` unless you intentionally change the model configuration.

If any signup or provider dashboard requires billing information contrary to your ₹0 rule, do not add billing; leave that provider key blank/unconfigured and keep that feature disabled.

## 4. Deploy and verify

1. Click **Deploy Blueprint**.
2. Wait for the build and start commands to finish.
3. Open the assigned `onrender.com` URL.
4. Test the Compare Live Prices tab first; this does not call Gemini merely by opening the page.
5. For a travel itinerary, expect Gemini/Tavily/Firecrawl API usage. Do not keep retrying if a request fails; inspect Render logs first.

## Scope and limitations

- The service is a research-backed itinerary MVP with optional provider price snapshots.
- SerpApi Google Flights/Hotels results are snapshots, not a booking confirmation. Search requests consume the provider's quota.
- RailRadar integration is timetable-only in this app; it does not claim free/verified live seat inventory or fares. Use official IRCTC to confirm.
- Bus results are external route links; automatic live bus inventory is not integrated.
- Budget totals generated by the LLM are estimates unless explicitly backed by a provider quote.
- Render Free has usage and sleep/resource limitations; after inactivity, the first visit can be slow. It may not be suitable for a production-critical app.
- The app does not book or reserve tickets or rooms.
